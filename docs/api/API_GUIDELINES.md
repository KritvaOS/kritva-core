# API Documentation Guidelines

Every public API document should describe:

1. Purpose
2. API surface
3. Semantics
4. Ownership and lifetime
5. Lifecycle interaction
6. Error behavior
7. Thread-safety
8. Allocation/blocking/real-time expectations
9. Compatibility rules
10. Security considerations
11. Examples where useful
12. Related requirements
13. Related headers
14. Related tests
15. Explicit exclusions

Do not duplicate the entire C++ header. Document the contract and behavior.
